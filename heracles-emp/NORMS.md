# NORMS — binding rules for every agent and script in heracles-emp

This directory is the empirical record for the paper. Every number in the paper must trace to a
script and a run in this directory. If a rule below blocks you, stop and say so. Do not work around it.

## A. Scope: only what the theorems cover

1. **Models.** Exactly two families, with no biases, no extra layers, no normalisation and no other
   nonlinearity.
   - *Product (multilinear) network:* f(x)[c] = Σ_i u_{i1}(a_1) ⋯ u_{in}(a_n) · w_i(c), with ν = n+1.
   - *Power (polynomial) network:* f(x)[c] = Σ_i (u_{i1}(a_1) + ⋯ + u_{in}(a_n))^n · w_i(c), with
     ν = n+1.
   - Inputs are one-hot, so u(a) is the a-th entry of a weight vector u ∈ R^p.
2. **Which claims may use which model.**
   - Count and share predictions at q < ν are theorems for product networks, via their
     interference-free class optimum. Those experiments therefore use product networks only.
   - Power networks may be used only for the statements the paper proves for them: the universal
     ceiling for all q, and the q = ν dense endpoint. The dense endpoint is attained at n = 2, q = 3
     (Morwani); for n ≥ 3 it is a statement about the bound's maximiser, and must be labelled so.
   - Never extrapolate a result to a model family or optimiser the theorems do not cover.
3. **Task.** The full table D_p = {(a_1, …, a_n) → a_1 + ⋯ + a_n mod p}, with p an odd prime. There is
   no train/test split: the theory is about the full-table margin.
4. **Objective.** Mean cross-entropy over D_p plus λ · Σ_i ‖ω_i‖_2^q, where
   ‖ω_i‖_2² = Σ_t ‖u_{it}‖² + ‖w_i‖² and 2 ≤ q ≤ ν. We write s = ν/q.
5. **Optimisers.**
   - Allowed: full-batch gradient descent (default), or SGD with or without heavy-ball / Nesterov
     momentum.
   - The penalty is always an explicit term in the gradient, never decoupled.
   - Forbidden: Adam, AdamW, RMSprop, Adagrad, Lion, Muon, sign methods, gradient clipping, gradient
     noise.
   - LR schedules and λ schedules are allowed if declared in the recipe.
6. **Precision** (amended 2026-09-25 16:55 IST by the author).
   - TRAINING is float32 with TF32 DISABLED everywhere:
     - `torch.backends.cuda.matmul.allow_tf32 = False`
     - `torch.backends.cudnn.allow_tf32 = False`
     - `torch.set_float32_matmul_precision('highest')`
   - Each run asserts these at startup and records them in config.json.
   - MEASUREMENT (margins, spectra, metrics) is float64: weights are cast to float64 before measuring.

## B. Isolation and provenance

7. **Self-contained.**
   - All code, configs, runs and reports live in heracles-emp/. Nothing is imported or read from the
     rest of the repo: no old scripts, no old run data, no old results.
   - Allowed dependencies are only the pinned third-party packages in heracles-emp/pyproject.toml.
   - You may read the paper and the old docs for *definitions*. Any idea taken from old code must be
     re-implemented here and pass the tests here.
8. **What every training run leaves behind.** Each run is one directory under its experiment's
   runs/, and is immutable once finished. It contains:
   - `config.json`:
     - model, n, ν, p, q, s, width, λ and its schedule, the optimiser and every hyperparameter,
       steps, init scheme and scale, seed, dtype;
     - package versions, the sha256 of every code file used, the hostname, and start/end times.
   - `log.csv`: at fixed intervals, the step, CE, penalty, total loss, gradient norm, margin,
     normalised margin and learning rate.
   - The final weights (`final.pt`).
   - `metrics.json`: every registered metric (see E).
9. **Nothing is ever omitted.**
   - Every launched run appears in the experiment's RUNS.csv with a status: ok, not_converged,
     diverged, crashed or invalid.
   - A rerun gets a new run id, and the old run stays listed with the reason.
   - Deleting or overwriting run directories is forbidden.
10. **Seeds.** Deterministic seeding (torch, numpy, python), with the seed list declared in advance.
11. **Reproducibility.** `reproduce.sh` in each experiment regenerates predictions, runs and
    analysis from scratch.

## C. Preregistration

12. **PREREG.md before evaluation.** Before any evaluation run of an experiment, write PREREG.md,
    containing:
    - the claim under test and its paper reference;
    - the exact predictions, generated by core code and saved to `predictions.json`;
    - the full run grid and seeds;
    - the frozen training recipe;
    - the convergence criterion and the exclusion rules;
    - the full list of metrics;
    - what counts as a match and what counts as a mismatch;
    - the expected compute.

    Stamp it with the output of `date`.
13. **PREREG.md is then frozen.** It is never edited once evaluation runs start. Any change goes in
    AMENDMENTS.md with a timestamp and reason, and results under an amended protocol are reported
    separately.
14. **Tuning.** Hyperparameter tuning is allowed only when:
    - (a) it is a declared TUNING phase, with every tuning run logged;
    - (b) its objective is optimisation quality only (the regularised loss reached, stationarity,
      stability of the normalised margin), and **never** agreement with a theoretical prediction;
    - (c) the frozen recipe is written down before evaluation;
    - (d) tuning runs are not counted as evaluation data.

## D. Convergence and exclusions

15. **Convergence.** The criterion is declared in advance (a core default is in core/RECIPES.md).
    - Non-converged runs are reported and analysed separately, never silently dropped.
    - Diverged and crashed runs are listed.
    - Exclusions follow only the pre-declared rules.

## E. Metrics and analysis

16. **Every metric, every time.** Every prediction is scored with ALL registered agreement metrics
    in core/metrics.py (counts under every definition, share agreement, margin ratios), never a
    hand-picked one.
    - Report per-run values, and aggregates with n and bootstrap uncertainty over seeds.
    - R² is always reported together with the other metrics, never alone.
17. **Controls.** Every experiment includes a positive control (a constructed network whose answer
    is known exactly, which must score as a perfect match) and a null baseline where one makes
    sense (for example random-init or random-allocation networks).
18. **Traceability.** Every number and figure in REPORT.md is regenerated by a named script in that
    experiment's analysis/, and REPORT.md names the script next to each number.
19. **Honest reporting.** Mismatches and nulls are reported as prominently as matches. Use no
    adjective the numbers do not support. State plainly which claims are theorems, which are
    measurements, and which are outside the theorems' scope.

## F. Compute (amended 2026-09-25 16:55 IST by the author: pods allowed)

20. **Where things run.**
    - Local CPU: development, tests, and small jobs.
    - RunPod GPU pods: the evaluation sweeps.
    - SECURE CLOUD ONLY (author, 17:00 IST). The default is an RTX 5090 (secure, $0.99/h). An RTX
      4090 (secure, $0.74/h) is the fallback when 5090 stock is out; a fallback is flagged, never
      silent.
21. **Who owns pods** (amended 17:25 IST by the author: the EMPIRICAL LEAD agent now owns pod lifecycle — it creates, assigns and deletes pods itself, secure cloud only, and logs every pod in COMPUTE.md; the text below applies to any other agent). **Previously:** The ORCHESTRATOR alone creates and deletes pods, and keeps the ledger in
    COMPUTE.md: pod id, GPU, $/h, start/stop time, and which experiment used it.
    - Experiment agents use only the pods assigned to them there, and never create or delete pods.
    - When an agent's results are pulled and verified, it messages the orchestrator.
22. **Limits.**
    - Every single training run must finish within 2 hours of wall clock. The FULL sweep must finish within 2 hours of wall clock (author, 17:25 IST).
    - NO heavy compute on the author's laptop: only file editing and smoke tests under 30 s. Tests, programme enumeration, tuning and sweeps all run on pods (author, 17:25 IST).
    - The total budget is USD 40.77, including idle time.
    - No pod sits idle; results are pulled and verified before a pod is released.
23. **Use the GPU efficiently.**
    - Batch independent runs of the same shape (seeds, q values, λ) in lockstep on one GPU where
      possible. The per-run results must be identical to running them alone, and a test must show
      this.
    - Each batched run keeps its own run directory and provenance, exactly as in B8.
24. **Local runs** go through core/runner.py, which enforces ≤ 6 concurrent CPU jobs with 1 thread
    each.

## G. Logging

22. **LOG.md.** Each experiment keeps a chronological, timestamped LOG.md of everything done: code
    written, tests run, runs launched, bugs found (and which runs they affected), fixes and reruns.
23. **Bugs.** A bug that affects finished runs marks those runs `invalid` in RUNS.csv (they are not
    deleted). They are then rerun under new ids, and the whole chain is logged.
